---
name: architecture-decision
description: Evaluate and document a consequential CraftDock architecture choice as an ADR, especially Docker Desktop access, Agent transport, authentication, storage, or tunnels. Use for design decisions; not routine implementation.
---

1. Read the specification and architecture decision log.
2. Define the problem, accepted constraints, and explicit non-goals.
3. Compare 2–3 feasible options on security, complexity, Windows/Linux compatibility, operations, and testing.
4. Identify unknowns requiring a proof-of-concept rather than guessing.
5. Recommend an option and request approval before marking it Accepted.
6. Create `docs/adr/NNNN-short-title.md` using the ADR template, with validation steps and consequences.
7. Update the decision log and any affected specification sections after acceptance.
